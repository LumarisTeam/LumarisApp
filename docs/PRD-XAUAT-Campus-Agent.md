# PRD｜光序校园助手 · XAUAT 专版

## 1. 摘要

面向西安建筑科技大学学生，在光序新增「校园助手」。学生可以在同一处查个人考试安排和校园办事资料。独立 Go 服务调用 Luminous 与 LuckyWiki 的 MCP，光序通过 Flutter GenUI 将结果呈现为考试卡片或带原文链接的百科卡片。

## 3. 背景

光序已有教务登录、考试卡片和 MCP 配置与连通性检测。Luminous 的 `/mcp` 提供考试查询，调用需要教务会话。LuckyWiki 的 `/api/mcp` 支持搜索和读取已发布文章。首版把这些能力接入一个对话入口，让学生直接看到当前任务所需的信息。 [光序考试卡片](../lib/ui/pages/home_page/exam_card.dart) · [光序 MCP 检测](/Users/luckyfish/Documents/Project/FlutterProjects/ios_club_app/lib/features/mcp/services/mcp_probe_service.dart) · [Luminous MCP](/Users/luckyfish/Documents/Project/GolangProjects/Luminous/internal/mcpserver/server.go) · [LuckyWiki MCP](/Users/luckyfish/Documents/Project/WebstormProjects/luckywiki/docs/MCP-INTEGRATION.md)

## 4. 目标与验收

首版内测交付前，在一台 iPhone 上通过以下两个场景：

1. **查询下一场考试。** 使用有待考记录的 XAUAT 测试账号，输入「我下一场考试是什么时候」。同一条回复内展示考试卡片，科目、时间、地点与 Luminous 返回的最近一场未开始考试一致。
2. **查询校园办事资料。** 输入「校园卡丢了怎么补办」，显示基于 LuckyWiki 已发布文章的办理摘要，点卡片能打开对应原文。若百科尚无该主题的文章，联调前选定一条已有原文的校园办事题，按相同标准验收。

异常场景一并验收。登录失效时可返回光序既有登录流程，确无待考记录与教务接口错误显示不同提示，百科查无文章时直接说明，组件无法渲染时将已取得的结果显示为文字。

## 5. 首版用户

聚焦两个任务场景。同一名 XAUAT 学生可以在不同时间遇到两种需求。

- **核对个人考试安排的学生**需要确认自己接下来在哪儿、几点考试。
- **第一次办理校园事务的学生**需要弄清办理步骤，并能回到原文核对。

## 7. 方案

### 7.1 用户流程

从光序进入「校园助手」，输入问题，查看简短回答和卡片。查询个人考试时使用本人教务会话，未登录或会话过期时提示登录后重试。百科卡片提供「查看原文」。建议首版允许学生不登录教务即可查公开百科。

### 7.2 首版功能

- **独立 Go 服务**接收问题和短期对话上下文，判定任务、调用工具并返回文字与界面数据。服务端固定学校为 `XAUAT`，仅开放 `get_exam_arrangements`、`search_wiki`、`get_article`。按北京时间从教务结果中筛选最近一场未开始的考试，科目、时间和地点直接取自工具结果。百科回答基于检索后读取的原文，链接由服务端根据文章路径生成。
- **光序接入 GenUI**，在本地注册「考试卡片」和「百科来源卡片」。Agent 根据任务选择和组合目录里的组件，Go 服务校验组件类型与字段，Flutter 负责渲染已注册的组件。考试事实和百科链接由工具结果填充。客户端遇到未知组件或版本时显示同条回复的文字内容。 [Flutter 自定义组件与接入指南](https://docs.flutter.dev/ai/genui/get-started)
- **授权与数据**。Go 服务按当前用户校验个人查询授权，由认证层把教务会话凭证注入 Luminous 调用。模型和 LuckyWiki 仅接收完成各自任务所需的内容，教务 Cookie、学号及服务密钥均排除在模型输入、百科请求和日志之外。首版在请求内处理个人考试结果，日志只记录工具名、耗时和错误类别等运行指标。

### 7.3 仓库与接口

新建独立 Go 仓库，暂名 `xauat-campus-agent`，单独部署。Go 侧分别适配 Luminous 的 Streamable HTTP 与 LuckyWiki 的 MCP 接口。LuckyWiki 现有路由支持直接 POST 返回 JSON，可作为联调起点。光序调用 Go 对话接口，建议用 HTTP 流式返回文字和 A2UI 界面消息。GenUI 目前为实验性 SDK，先在光序现有 Flutter 工具链上验证两张卡片，再固定兼容版本与组件协议。 [LuckyWiki MCP 路由](/Users/luckyfish/Documents/Project/WebstormProjects/luckywiki/app/api/mcp/route.ts) · [Flutter GenUI SDK](https://docs.flutter.dev/ai/genui)

### 7.4 开工时验证

- **个人授权。** 确认光序的教务会话如何安全授予 Go 服务使用，并用两个账号验证隔离。选定授权方式后再开启个人考试查询。
- **验收数据。** 准备有待考记录的测试账号，确认考试时间和地点字段可用，以及 LuckyWiki 的已发布文章覆盖所选办事题。确认模型供应方、部署环境和限流配额。

## 8. 发布

先用样例数据验证 Go 到 Flutter 的两张卡片，再接入真实 MCP 并在 iPhone 上验证两条完整流程。建议首轮预留 **1–2 周**，前提是测试账号、百科凭据和教务授权路径可用。通过后在 XAUAT 版开启小范围内测，以功能开关控制入口。课表、成绩、校车、电费、跨校、多端发布和可执行校园操作留到后续版本评估。
